# Security policy

## Reporting a vulnerability

Please do not report vulnerabilities in public issues. Use GitHub's private
vulnerability reporting/security advisory flow for this repository. Include:

- the affected commit or version;
- concise reproduction steps and expected impact; and
- a suggested mitigation, if known.

Please allow time for triage before disclosing the issue publicly. Reports that
are only suspected scam content should use the normal project channels rather
than the vulnerability process.

Never include API keys, authentication tokens, private job postings, or personal
data in reports. Redact secrets from logs and replace real people, employers,
email addresses, and URLs with synthetic examples.

## Supported versions

Only the latest version on the default branch is actively maintained for
security fixes. Pin deployments to a reviewed commit and rotate provider keys
if they may have been exposed.

The application is a screening aid and should not receive financial
credentials, identity documents, or one-time passwords.
